# 个人博客开发实施清单

## 1. 文档目的

这份清单用于把整体规划拆成具体可执行任务。

后续开始开发时，我们就按照这份清单逐步推进，避免遗漏基础工作，也避免一开始就陷入细节。

## 2. 当前开发目标

第一阶段目标：
- 完成一个可上线的个人博客 MVP

MVP 应包含：
- 首页
- 博客列表页
- 博客详情页
- 标签页
- About 页
- 深色模式
- 内容系统
- SEO 基础
- 静态部署能力

## 3. 阶段划分

### 阶段 A：项目初始化

目标：
- 把 Nuxt 4 基础项目搭起来

任务清单：
- 初始化 `Nuxt 4` 项目
- 配置 `TypeScript`
- 配置基础 `package.json` 脚本
- 建立基础目录结构
- 建立 `.gitignore`
- 确认项目可以正常启动和构建

完成标准：
- 本地可以运行开发环境
- 本地可以成功构建

## 4. 阶段 B：基础能力接入

目标：
- 接入博客项目最重要的基础能力

任务清单：
- 安装并配置 `@nuxt/content`
- 安装并配置 `Tailwind CSS`
- 评估是否接入 `Nuxt UI`
- 建立全局样式入口
- 建立主题变量体系
- 建立深色模式切换机制
- 设置主题偏好持久化

完成标准：
- 明暗模式可切换
- 全局样式和主题 token 生效
- 内容目录可被识别

## 5. 阶段 C：内容系统搭建

目标：
- 让博客具备“写文章和展示文章”的基础能力

任务清单：
- 建立 `content/posts/` 目录
- 设计文章 frontmatter 结构
- 配置内容 schema
- 添加 2 到 3 篇示例文章
- 实现 `draft` 内容过滤策略
- 统一文章日期和标签处理逻辑
- 计算文章阅读时长

完成标准：
- 示例文章可以被正确读取和渲染
- 草稿内容不会进入生产展示

## 6. 阶段 D：全局布局与导航

目标：
- 建立网站基础骨架

任务清单：
- 建立默认布局
- 实现头部导航
- 实现页脚
- 增加主题切换按钮
- 增加社交链接入口
- 设置全站容器宽度和基础间距

完成标准：
- 所有页面共用统一布局
- 移动端和桌面端导航可用

## 7. 阶段 E：页面开发

### E1 首页

任务清单：
- 搭建 Hero 区域
- 展示你的简介
- 展示最新文章
- 展示标签入口
- 增加文章页和 About 页入口

完成标准：
- 首页能快速表达“你是谁”和“博客写什么”

### E2 博客列表页

任务清单：
- 建立 `/blog`
- 获取全部文章并按时间倒序
- 展示文章标题、日期、描述、标签
- 预留空状态

完成标准：
- 所有文章可被浏览

### E3 博客详情页

任务清单：
- 建立 `/blog/[slug]`
- 渲染文章正文
- 展示文章头部信息
- 展示标签
- 展示阅读时长
- 增加上一篇 / 下一篇
- 处理文章不存在时的错误页

完成标准：
- 任意文章都能独立访问和阅读

### E4 标签页

任务清单：
- 建立 `/tags/[tag]`
- 聚合同标签文章
- 展示标签名和文章列表

完成标准：
- 标签归档可用

### E5 About 页

任务清单：
- 建立 `/about`
- 展示个人介绍
- 展示擅长方向 / 兴趣 / 外部链接

完成标准：
- About 页具备完整的自我介绍能力

## 8. 阶段 F：文章阅读体验优化

目标：
- 把文章页从“能看”提升到“好看、好读”

任务清单：
- 统一 Markdown 排版样式
- 优化标题、列表、引用块样式
- 优化代码块样式
- 优化图片和封面图表现
- 评估是否增加文章目录
- 评估是否增加复制链接功能

完成标准：
- 文章阅读体验统一且稳定
- 深色模式下阅读不吃力

## 9. 阶段 G：SEO 与站点能力

目标：
- 让博客具备上线基础能力

任务清单：
- 配置全站 SEO 默认值
- 配置页面级 title / description
- 配置文章页 SEO
- 设置 canonical
- 配置 Open Graph
- 生成 sitemap
- 生成 RSS
- 配置 robots

完成标准：
- 页面 metadata 正常
- RSS 和 sitemap 可用

## 10. 阶段 H：系统页面与异常处理

目标：
- 完善网站边界体验

任务清单：
- 自定义 404 页面
- 自定义错误页面
- 处理空列表或异常状态

完成标准：
- 不存在的页面和异常状态有明确反馈

## 11. 阶段 I：响应式与深色模式检查

目标：
- 确保整体体验稳定

任务清单：
- 检查移动端首页布局
- 检查移动端文章页布局
- 检查代码块横向滚动
- 检查深色模式下正文对比度
- 检查深色模式下按钮、标签、边框
- 检查主题切换是否有闪烁

完成标准：
- 常见屏幕尺寸下都可正常使用
- 深色模式体验稳定

## 12. 阶段 J：部署准备

目标：
- 让项目进入可上线状态

任务清单：
- 确定部署平台
- 配置构建命令
- 配置输出方式
- 做一次生产构建验证
- 部署预览环境
- 检查线上 SEO 和资源路径

完成标准：
- 项目可以成功上线访问

## 13. 建议开发顺序

建议实际执行顺序如下：

1. 项目初始化
2. 基础能力接入
3. 内容系统搭建
4. 全局布局与导航
5. 首页
6. 博客列表页
7. 博客详情页
8. 标签页
9. About 页
10. 文章阅读体验优化
11. SEO 与系统页面
12. 响应式检查
13. 部署

## 14. 第一阶段验收标准

当以下条件都满足时，可以认为第一版 MVP 完成：

- 可以新增 Markdown 文章并自动出现在博客中
- 首页、博客列表页、文章页、标签页、About 页都可用
- 浅色和深色模式都完整可用
- 移动端和桌面端布局稳定
- SEO 基础已接入
- 项目能成功构建并部署

## 15. 后续扩展清单

第一版上线后可以继续排期：

- Projects 页面
- 全站搜索
- 文章目录
- 精选文章机制
- 系列文章
- 阅读进度条
- 第三方统计
- 社交分享图

## 16. 我们接下来最推荐的工作方式

建议按下面节奏推进：

1. 先完成所有规划文档
2. 再初始化 Nuxt 项目
3. 先做基础骨架和主题系统
4. 再做内容系统和页面
5. 最后做 SEO、部署和细节优化

这样做的好处是：
- 大方向不会反复变
- 页面风格更统一
- 深色模式不会变成后补工程
- 后续开发节奏更顺
