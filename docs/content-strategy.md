# 个人博客内容策略与文案草案

## 1. 文档目标

这份文档用于提前规划博客的内容表达方式，避免项目开始开发后才临时决定：

- 首页写什么
- About 页怎么组织
- 博客主要写哪些内容
- 每种内容用什么语气和结构

对于个人博客来说，内容策略和代码架构同样重要。

## 2. 内容定位

这个博客不只是“发文章的地方”，它还应该承担：

- 介绍你自己
- 展示你的思考方式
- 累积你的知识资产
- 让别人通过内容认识你

所以内容风格应该围绕两个核心：
- 有价值
- 有个人感

## 3. 整体内容结构

建议第一阶段先围绕这 3 类内容来组织：

- 个人介绍内容
- 博客文章内容
- 站点辅助内容

### 3.1 个人介绍内容

主要放在：
- 首页首屏
- 首页简介
- About 页面

目标：
- 让访客快速理解你是谁
- 让页面看起来不像“匿名内容站”

### 3.2 博客文章内容

主要放在：
- 博客列表页
- 博客详情页
- 标签页

目标：
- 建立内容主线
- 逐步沉淀技术和个人思考

### 3.3 站点辅助内容

包括：
- 页脚说明
- SEO 描述
- 社交链接文字
- 404 页面文案

目标：
- 让整个站点表达统一，不只是在正文里有语气

## 4. 首页内容策略

首页的任务不是“把所有内容都摆出来”，而是做 3 件事：

- 介绍你是谁
- 告诉别人这里有什么
- 引导访客去读文章

### 4.1 首页建议结构

建议模块如下：

1. Hero 首屏
2. 简介区
3. 最新文章区
4. 主题 / 标签区
5. 可选的“我最近在做什么”

### 4.2 首页 Hero 文案结构

Hero 最好包含：

- 你的名字或站点名
- 一句身份描述
- 一段 1 到 3 句的介绍
- 一个主按钮
- 一个次按钮

### 4.3 首页 Hero 文案模板

可以参考这种写法：

标题：
- `你好，我是 XXX`
- `我是 XXX，一名专注于 XXX 的开发者`

副标题：
- `这里记录我关于前端、产品、技术实践和个人成长的思考。`
- `我会在这里持续写下我做过的项目、踩过的坑，以及对技术的理解。`

按钮文案：
- `阅读博客`
- `了解我`

### 4.4 首页简介区建议

这部分建议回答：

- 我现在主要做什么
- 我关心什么主题
- 为什么会写这个博客

文案风格要简洁，不要过长。

### 4.5 最新文章区

建议展示：
- 最近 3 到 5 篇文章

这个模块的目标不是“放很多”，而是让人快速进入内容。

### 4.6 标签 / 主题区

建议展示：
- 你最常写的几个主题

比如：
- Nuxt
- Vue
- 前端工程化
- 产品思考
- 开发日常

## 5. About 页面内容策略

About 页不是简历复刻，而是更完整、更有温度的自我介绍。

它的目标是：
- 建立信任感
- 让人理解你的背景和方向
- 让访客知道你适合做什么、在关心什么

### 5.1 About 页建议结构

建议分成以下几个模块：

1. 简短自我介绍
2. 我的背景
3. 我在关注什么
4. 我擅长什么
5. 我的工作方式
6. 外部链接 / 联系方式

### 5.2 About 页文案方向

可以围绕这些问题来写：

- 你是谁
- 你在做什么类型的工作
- 你为什么喜欢这个方向
- 你长期想积累什么
- 你希望别人通过这个博客看到什么

### 5.3 About 页语气建议

- 真诚
- 平静
- 清楚
- 不要太官方
- 不要写成“求职自荐信”

## 6. 博客内容策略

### 6.1 第一阶段建议文章类型

建议先从以下几类文章开始：

- 技术实践总结
- 学习记录
- 项目复盘
- 工具或框架使用经验
- 个人思考类文章

### 6.2 适合这个博客的主题方向

你可以优先围绕这些主题写：

- Nuxt / Vue
- 前端开发经验
- UI 与交互实现
- 工程化和开发流程
- AI 辅助开发
- 个人项目记录

### 6.3 第一批文章建议

建议第一阶段先准备 3 到 5 篇文章，哪怕内容不长也没关系。

可以参考这些题目方向：
- 我为什么决定用 Nuxt 4 搭自己的博客
- 从 0 开始设计一个支持深色模式的个人博客
- 我最近的前端开发工作流
- 一次项目实践中的技术选择复盘
- 我希望这个博客记录什么

## 7. 文章结构建议

### 7.1 技术文章结构

推荐结构：

1. 问题背景
2. 为什么会遇到这个问题
3. 解决方案
4. 关键代码 / 实现思路
5. 总结和经验

### 7.2 复盘文章结构

推荐结构：

1. 项目背景
2. 目标
3. 做了什么
4. 遇到了什么问题
5. 最终收获

### 7.3 思考类文章结构

推荐结构：

1. 一个起点问题
2. 你的观察
3. 你的判断
4. 你的结论

## 8. 文案语气规范

### 建议语气

- 清楚
- 真诚
- 不装腔作势
- 有思考感
- 有个人表达，但不过度自我表演

### 不建议的表达方式

- 过度营销化
- 过度夸张
- 很空的口号式表达
- 用太多大词但没有具体内容

## 9. 页面文案草案

### 9.1 首页标题草案

你可以从这几种方向里选一种，后续我们再细化：

方向 A：
- `你好，我是 XXX`
- `这里记录我写过的代码、做过的项目和持续积累的思考。`

方向 B：
- `我是 XXX，一名专注于前端体验与产品实现的开发者。`
- `这个博客用来记录技术实践、项目复盘和一些长期有价值的内容。`

方向 C：
- `写代码，也写下为什么这样做。`
- `这是我的个人博客，记录开发、设计、产品和持续学习。`

### 9.2 首页按钮草案

- `阅读文章`
- `了解我`

### 9.3 About 页开头草案

示例：

`你好，我是 XXX。`

`我主要关注前端开发、交互体验和内容型产品。我希望把做项目时真正有价值的经验、踩过的坑和形成的方法论，长期整理在这里。`

### 9.4 页脚草案

可以用比较轻的表达：

- `记录代码、项目和长期思考。`
- `用 Nuxt 4 构建。`

## 10. 标签策略

### 标签使用原则

- 每篇文章标签控制在 2 到 4 个
- 标签尽量长期稳定
- 不要出现大量只用一次的标签

### 第一版推荐标签池

- `nuxt`
- `vue`
- `frontend`
- `engineering`
- `ui`
- `workflow`
- `project`
- `notes`

## 11. SEO 文案建议

### 站点描述

站点 description 建议包含：
- 你是谁
- 你写什么
- 网站的长期定位

示例方向：

`XXX 的个人博客，记录前端开发、Nuxt、产品实践与长期积累的技术思考。`

### 文章描述

每篇文章都应该有一句清晰的 description，用于：
- 列表摘要
- 搜索结果摘要
- 社交分享摘要

## 12. 第一阶段需要准备的真实内容

在开始开发前，建议你后续准备这些真实内容：

- 你的名字或站点名
- 一句身份描述
- 一段首页简介
- About 页正文初稿
- 社交链接
- 3 到 5 篇示例文章标题
- 这些文章的标签

## 13. 当前结论

内容策略的重点不是“写很多”，而是先把以下内容写得清楚：

- 你是谁
- 这个博客写什么
- 为什么值得读
- 第一批文章准备怎么组织

只要这一层先明确，后面无论是页面设计还是代码实现，都会更稳定、更自然。
