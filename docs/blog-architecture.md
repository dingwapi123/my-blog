# 个人博客整体架构规划

## 1. 项目目标

使用 `Nuxt 4` 搭建一个以内容为核心的个人博客网站。

核心原则：
- 不做后端
- 不做登录和用户系统
- 重点提升阅读体验
- 要有清晰的个人表达和品牌感
- SEO 友好，适合静态部署
- 后续维护成本低
- 从第一版开始就支持深色模式

这个项目不只是“文章列表”，而是一个“个人主页 + 博客内容”的组合型网站。

## 2. 项目定位

### 主要作用

这个网站主要承担 3 个角色：
- 展示你是谁，你在做什么
- 发布你的文章和思考
- 作为你的公开知识库和内容沉淀空间

### 目标访客

- 招聘方、潜在合作方
- 阅读技术文章的开发者
- 对你感兴趣的读者、朋友
- 未来的你自己，把博客当作长期积累的内容仓库

### 网站气质

- 简洁但不空
- 有个人风格，但保持专业
- 可读性强
- 现代、克制、重视排版

## 3. 技术方案

### 推荐技术栈

- 框架：`Nuxt 4`
- 语言：`TypeScript`
- 内容系统：`@nuxt/content`
- 样式方案：`Tailwind CSS`
- UI 基础组件：按需使用 `Nuxt UI`
- 部署方式：静态部署到 `Vercel`、`Netlify` 或 `Cloudflare Pages`

### 为什么这样选

- `Nuxt 4` 自带路由、布局、SEO、渲染策略，适合做内容网站。
- `@nuxt/content` 很适合博客这种“文件即内容”的模式，不需要额外 CMS。
- 静态部署成本低，部署简单，后期几乎没有运维压力。
- `TypeScript` 能让内容结构和页面逻辑更稳定，后面扩展也更舒服。

### 渲染策略

推荐主方案：
- 全站静态生成

原因：
- 最适合“无后端博客”
- 性能好
- SEO 好
- 部署和回滚都简单

## 4. 项目范围

### 第一阶段 MVP

第一版建议包含：
- 首页
- 博客列表页
- 博客详情页
- 标签归档页
- About 页面
- 全局布局：导航、页脚
- 深色模式切换
- Markdown 文章系统
- SEO 基础配置
- 404 页面
- RSS 和 sitemap

### 第二阶段可扩展功能

上线后可以继续做：
- Projects 页面
- 搜索
- 阅读进度条
- 文章目录
- 系列文章支持
- 精选文章
- 相关文章推荐
- 第三方统计
- Newsletter 或订阅入口

### 当前不做

- 后端 API
- 登录 / 注册
- 管理后台
- 数据库
- 评论系统
- 多语言
- 复杂动画系统

## 5. 详细功能清单

### 5.1 全局功能

- 响应式布局，兼容桌面端、平板、移动端
- 明暗主题切换
- 记住用户主题偏好
- 全局 SEO 默认配置
- Open Graph / 社交分享元信息
- 无障碍和对比度基本可用
- 轻量级页面过渡效果

### 5.2 首页

- Hero 区域，展示你的名字、身份、核心一句话介绍
- 简短介绍这个博客主要写什么
- 最新文章区域
- 热门标签或主题入口
- About 页面入口
- 查看全部文章入口
- 可选的“最近在做什么”或“当前关注方向”

### 5.3 博客列表页

- 按时间倒序展示文章
- 每篇文章显示标题、日期、描述、标签
- 支持精选文章展示
- 为后续筛选或搜索预留结构
- 后续可扩展分页或加载更多

### 5.4 博客详情页

- 文章标题
- 发布时间和更新时间
- 标签
- 阅读时长
- 封面图支持
- Markdown 富文本渲染
- 代码块样式
- 上一篇 / 下一篇导航
- 可选文章目录
- 可选复制链接功能

### 5.5 标签系统

- 文章支持标签
- 每个标签有单独归档页
- 显示标签下的文章数量

### 5.6 About 页面

- 个人介绍
- 技能方向 / 关注领域
- 工作风格 / 兴趣
- 社交链接
- 联系方式说明

### 5.7 系统页面和基础能力

- 404 页面
- 自定义错误页
- RSS
- sitemap
- robots 配置

## 8. 内容模型设计

### 当前内容类型

第一阶段先只做：
- `posts`

后续可扩展：
- `projects`
- `notes`
- `pages`

### 文章 Frontmatter 建议字段

```yaml
title: "文章标题"
description: "用于列表摘要和 SEO 描述"
date: "2026-04-05"
updated: "2026-04-05"
tags:
  - nuxt
  - frontend
category: "engineering"
cover: "/images/posts/example-cover.jpg"
draft: false
featured: false
```

### 内容编写规则

- 标题尽量明确，便于搜索和理解
- description 既要适合卡片展示，也要适合 SEO
- 标签不要过多，控制在合理范围
- 日期格式统一
- `draft: true` 的文章在生产环境不展示

## 9. 深色模式方案

深色模式是必做功能，不是后补功能。

### 功能要求

- 支持浅色和深色两套主题
- 首次访问时跟随系统主题
- 用户可以手动切换
- 用户选择需要被记住

### 设计原则

- 不能简单粗暴反色
- 保持足够对比度，但不要刺眼
- 深色背景避免纯黑，建议使用偏暖或偏墨色的深色
- 强调色在明暗模式下要保持一致风格
- 文章正文在深色模式下要单独检查可读性

### 主题变量建议

建议使用语义化主题变量，而不是直接写死颜色：
- `--bg`
- `--bg-elevated`
- `--text`
- `--text-muted`
- `--border`
- `--accent`
- `--accent-soft`

### 视觉方向建议

浅色模式：
- 偏暖白或柔和浅底
- 深色正文
- 低对比边框
- 有节制的强调色

深色模式：
- 深墨色或深炭灰背景
- 柔和的浅色正文
- 卡片和导航比背景略微抬起
- 强调色重新调校保证对比度

### 深色模式细节

- 头部提供主题切换按钮
- 切换动画轻微且自然
- 代码块要针对深色模式单独设计
- 图片、封面图需要兼顾明暗两套背景效果

## 12. 开发里程碑

### 里程碑 1：基础搭建

- 初始化 Nuxt 4 项目
- 接入 Tailwind CSS
- 接入 `@nuxt/content`
- 建立基础路由和布局
- 建立主题变量和深色模式机制

### 里程碑 2：核心页面

- 完成首页
- 完成博客列表页
- 完成博客详情页
- 完成 About 页面
- 完成标签归档页

### 里程碑 3：内容与体验完善

- 建立文章 schema 和示例内容
- 统一文章排版
- 完善代码块样式
- 补齐导航和空状态
- 完成 404 页面

### 里程碑 4：上线准备

- 完成 SEO 默认配置
- 接入 sitemap 和 RSS
- 完成构建与静态部署
- 做一次响应式和深色模式全站检查

## 13. 开发优先级

真正开始写代码时，建议按这个顺序推进：

1. 内容系统和项目骨架
2. 全局布局和主题系统
3. 核心页面
4. 文章阅读体验
5. SEO 和部署
6. 增强功能

## 14. 当前结论

这个博客最适合做成一个：

`Nuxt 4 + @nuxt/content + 静态部署 + 原生支持深色模式`

的内容型网站。

第一版重点应该放在：
- 结构清晰
- 阅读体验好
- 深色模式做扎实
- 首页有个人表达
- 写作流程足够轻

只要这几件事先打稳，后面开始视觉设计和代码实现时就不会反复推翻基础方案。
